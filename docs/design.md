# アプリケーション設計ドキュメント

## 概要

本ドキュメントは、Autodesk Maya用MikuMikuDance (MMD) 連携プラグイン「maya_mmd_tools」の設計について記述します。
このプラグインは、MMDのファイルフォーマット（.pmd, .pmx, .vmd）とMayaシーンとの間で、モデル、モーション、ポーズなどのデータを相互に変換する機能を提供する。

## プロジェクト目標

- MMDアセットをMaya環境で利用可能にし、MMDアニメーション制作を支援する。
- Mayaで作成したアセットをMMD形式で出力し、MMDコミュニティでの利用を促進する。
- MMDとMayaのワークフローをシームレスに連携させ、クリエイターの生産性を向上させる。

## 要件定義

### 機能要件

#### インポート機能
- PMD/PMXモデルのインポート（メッシュ、材質、テクスチャ、ボーン、スキニング、モーフ、表示枠、剛体、ジョイント）
- VMDモーションのインポート（ボーンアニメーション、モーフアニメーション、カメラ、照明、セルフシャドウ）
- VPDポーズのインポート

#### エクスポート機能
- PMD/PMXモデルのエクスポート
- VMDモーションのエクスポート
- VPDポーズのエクスポート

#### モデル編集機能
- MMDモデルの簡易編集機能（材質、モーフ、物理演算設定など）
- 日本語や中国語から英語への一括翻訳機能
- ポリゴンの自動四角ポリゴン化機能

#### ユーティリティ機能
- MMDモデルの頂点数、ボーン数、モーフ数の統計
- モデルのメンテナンス機能（不要なボーンやモーフの削除、重複ボーンの統合）
- モデルの自動リギング機能（ボーンの自動配置、スキニングの自動設定）
- MMD用Toonシェーダーのアタッチとテクスチャの設定
- （拡張）mGearやAdvanced Skeleton等のリギングツールとの連携機能
- （拡張）ゲームエンジン向けの物理演算の設定（剛体、ジョイント）のインポート/エクスポート

### 非機能要件

- **対応プラットフォーム:** Autodesk Maya 2020～2026 (Windows 11 macOS 13 Linux)
- **パフォーマンス:** 大規模なモデルやモーションデータ（例：頂点数10万以上、ボーン数200以上）を現実的な時間（数分以内）で処理できること。
- **互換性:** 主要なMMDモデルやツールで作成されたデータとの互換性を維持する。
- **ユーザビリティ:** 直感的なUIを提供し、Mayaユーザーが特別な知識なしに利用できること。
- **拡張性:** 将来的な機能追加（新しいモーフタイプ、物理演算エンジン対応など）が容易な設計であること。

## アーキテクチャ

### 全体構成

プラグインは以下の主要コンポーネントから構成される。

1.  **UI層 (`ui.py`):** ユーザーからの入力を受け付け、処理結果を表示する。
2.  **IO層 (`io/`):** インポート/エクスポートのメインロジックを担当する。
3.  **変換層 (`converters/`):** MMDデータ構造とMayaシーンオブジェクト間の相互変換を行う。
4.  **コア層 (`core/`):** MMDファイルの解析、Mayaの低レベルAPI操作など、プラグインの中核機能を担う。

### データフロー

#### インポート処理
1.  **UI層:** ユーザーがインポート対象のファイルとオプションを選択。
2.  **IO層 (`mmd_importer.py`):** ファイルパスを受け取り、ファイル形式（PMD/PMX/VMD）を判定。
3.  **コア層 (`mmd_parser.py`):** 該当するパーサー（`PmdParser`, `PmxParser`, `VmdParser`）を呼び出し、バイナリファイルを解析してPythonオブジェクトに変換。
4.  **変換層 (`converters/`):** 解析されたデータオブジェクトを各コンバーター（`mesh_converter.py`, `bone_converter.py`等）に渡し、Mayaのノード（メッシュ、ジョイント、ブレンドシェイプ等）を生成・設定する。
5.  **UI層:** 処理結果（成功、失敗、警告）をユーザーに通知。

#### エクスポート処理
1.  **UI層:** ユーザーがエクスポート対象のオブジェクトとオプションを選択。
2.  **IO層 (`pmx_exporter.py`等):** Mayaシーンからエクスポートに必要な情報を収集。
3.  **変換層 (`converters/`):** Mayaノードの情報をMMDデータ構造に変換。
4.  **コア層:** 変換されたデータオブジェクトをバイナリ形式にシリアライズし、ファイルに書き出す。
5.  **UI層:** 処理結果をユーザーに通知。

## UI/UX設計

### メインウィンドウ
- 「MMD Tools」というメインメニューをMayaのメニューバーに追加。
- インポート、エクスポート、ユーティリティ機能をまとめたウィンドウを提供。
- 各機能はタブで切り替え可能にする。

### インポート/エクスポートダイアログ
- ファイルパス指定フィールド。
- スケール設定、物理演算の有無、アニメーションの上書き/追加など、詳細なオプション設定。
- 処理の進捗を示すプログレスバーとログ出力エリア。

## データ構造設計

### MMDデータクラス (`core/pmx_data/`, `core/pmd_data/`, `core/vmd_data/`)
- MMDファイルの各要素（ヘッダ、頂点、材質、ボーン等）に対応するPythonクラスを定義。
- ファイルから読み込んだデータを格納し、コンバーターに渡すための中間表現として利用する。

### Mayaシーンとのマッピング
- **ボーン:** Mayaの`joint`にマッピング。親子関係、IK設定を再現。
- **メッシュ:** Mayaの`mesh`にマッピング。`skinCluster`でスキニング。
- **モーフ:** Mayaの`blendShape`にマッピング。
- **物理演算:** Mayaの`rigidBody`と`constraint`にマッピング。

### Mayaシーンの構成

以下の構成に従って、Mayaシーンを整理します。

```
CharacterName_Grp
├── Geometry_Grp (またはModel_Grp)
│   ├── CharacterName_Mesh
├── Skeleton_Grp (またはJoints_Grp)
│   ├── master
│   ├── manipulation_center
├── Controls_Grp (またはRig_Grp)
├── Simulation_Grp
│   ├── CharacterName_nucleus
│   ├── Clothing_Grp
│   ├── Hair_Grp
│   └── Collision_Grp
└── Extra_Grp (補助オブジェクト)
    ├── Locators_Grp
    ├── Constraints_Grp
    └── Utility_Nodes_Grp
```

## 日本語文字列変換設計

### 課題
MayaのASCII環境では、Shift-JISや日本語文字列の取り扱いに制限があります。MMDモデルには日本語のボーン名、モーフ名、材質名が含まれるため、Maya環境で安全に扱える形式への変換が必要です。

### 解決策：ハイブリッド変換方式

#### 基本方針
1. **辞書変換:** よく使われる日本語名には直感的な英語名を割り当て
2. **Base64変換:** 辞書にない日本語はBase64エンコードで安全に変換
3. **プレフィックス識別:** 変換方式を明確に識別可能にする

#### 実装仕様
```python
class MayaJapaneseConverter:
    def __init__(self):
        # 標準的なMMD用語の辞書
        self.jp_to_en = {
            "ボーン": "bone_jp",
            "左腕": "left_arm_jp", 
            "右腕": "right_arm_jp",
            "頭": "head_jp",
            "髪": "hair_jp",
            "表情": "expression_jp",
            "全ての親": "master_jp"
        }
        self.en_to_jp = {v: k for k, v in self.jp_to_en.items()}
        
        # 識別プレフィックス
        self.B64_PREFIX = "jpb64_"
        
        # Maya無効文字対応
        self.MAYA_INVALID_CHARS = {
            ':': '_colon_',
            ' ': '_space_',
            '-': '_dash_',
            '.': '_dot_',
            '|': '_pipe_'
        }
```

#### エラーハンドリング
- Base64デコード失敗時のフォールバック処理
- 文字エンコーディングエラーの適切な処理
- 変換失敗時のログ出力とユーザー通知

#### パフォーマンス考慮
- 大量のノード名変換に対応したキャッシュ機能
- 変換済み名前の重複チェック機能

### 使用場面
- PMX/PMDインポート時のノード名変換
- VMDインポート時のターゲット名照合
- エクスポート時の日本語名復元
