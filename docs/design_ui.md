# UI設計仕様書

## はじめに

このドキュメントは、Maya用MMD Toolsの新しいユーザーインターフェース（UI）の設計とアーキテクチャについて概説します。現在のUI実装（`mmd_tools/ui.py`）は単一のモノリシックなクラスであり、保守と将来の拡張において課題を抱えています。

この再設計の目標は、関心事を分離し、現代的なソフトウェア設計パターンを採用することで、よりモジュール化され、拡張性が高く、保守しやすいUIフレームワークを構築することです。

## 設計目標

- **モジュール性:** UIをより小さく、独立し、再利用可能なコンポーネントに分解します。
- **拡張性:** コアとなるUI構造に大きな変更を加えることなく、新しい機能やツール（例：モーフエディタ、物理ツール）を簡単に追加できるようにします。
- **保守性:** コードの可読性と構成を改善し、デバッグと将来の開発を簡素化します。
- **関心の分離:** UI（ビュー）とビジネスロジック（プレゼンター/コントローラー）を分離し、テストの容易性とコードの再利用性を向上させます。
- **ユーザーエクスペリエンスの向上:** 単一のダイアログからタブ形式のインターフェースに移行し、より整理され直感的なワークフローを提供します。

## アーキテクチャ

UIコードを構造化するために、**Model-View-Presenter (MVP)** に類似したデザインパターンを採用します。

- **ビュー (View):** データの表示とユーザー入力のキャプチャを担当するUIコンポーネント。これらはPySideを使用して実装されます。ビューの役割は、視覚的な要素の管理に徹し、すべてのユーザーアクションをプレゼンターに委譲することです。
- **プレゼンター (Presenter):** アプリケーションのロジックを処理する中間層。コアモジュール（例：インポーター、エクスポーター）からデータを取得し、ビューから受け取ったユーザー入力を処理し、ビューで表示するためにデータをフォーマットします。
- **モデル (Model):** アプリケーションのデータと状態を表します。我々のケースでは、`mmd_tools.settings`からの設定や、処理中のデータ（例：PMX/VMDデータ）が含まれます。

この分離により、UIコンポーネントがコアのアプリケーションロジックに直接結びつかないことが保証され、両方の管理と独立したテストが容易になります。

## PMXエディタのUI構成（参考）

再設計にあたり、高機能なMMDモデル編集ツールであるPMXエディタのUI構成を参考にします。PMXエディタは、複数の独立したウィンドウが連携して動作するアーキテクチャを採用しており、各ウィンドウが特定の役割を担っています。

- **Pmx編集ウィンドウ:**
  - モデルのヘッダ情報、頂点、材質、ボーン、モーフ、表示枠、剛体、ジョイントといった全要素の数値データを、タブを切り替えることで直接編集・確認できるメインウィンドウ。
  - スプレッドシート形式の表示が中心で、詳細なデータ編集に使用されます。

- **PmxViewウィンドウ:**
  - 3Dモデルを視覚的に表示するビューポート。
  - マウス操作による頂点やボーンの選択、移動、回転、拡大縮小といった直感的な編集が可能です。
  - ウェイトペイントや、限定的な物理演算のプレビューもこのウィンドウで行います。

- **TransformView (TView):**
  - VMDモーションを読み込み、モデルに適用して再生するための独立したウィンドウ。
  - 物理演算（剛体・ジョイント）の結果をシミュレーションし、実際のMMD環境に近い動きを確認できます。

- **サブウィンドウ群:**
  - 特定のタスクに特化した小さなウィンドウが多数用意されています。（例：ウェイト描画、材質の絞り込み表示、UV編集など）
  - これらのウィンドウはPmxViewやPmx編集ウィンドウから呼び出され、メインの編集作業を補助します。

### 本プラグインへの応用

PMXエディタの思想を取り入れ、本プラグインのUIを以下のように構成します。

- **メインウィンドウ (`MainWindow`):**
  - PMXエディタの「Pmx編集ウィンドウ」のように、タブ形式で各機能（インポート/エクスポート、モーフ編集、物理演算設定など）を切り替えるインターフェースを提供します。
  - MayaのUIに統合されるため、独立したウィンドウではなく、ドッキング可能なパネルとして設計します。

- **3Dビューポートとの連携:**
  - PMXエディタの「PmxView」の役割は、Mayaの標準ビューポートが担います。本プラグインは、選択や表示の切り替えなど、Mayaのビューポート機能を活用してユーザーにフィードバックを提供します。

- **プレビュー機能:**
  - PMXエディタの「TransformView」に相当する機能として、VMDモーションを読み込んでMayaのタイムラインにベイクし、プレビューする機能の実装を検討します。これにより、Maya上で直接アニメーションの確認が可能になります。

## コンポーネント設計

上記の思想に基づき、新しいUIはタブ付きレイアウト（`QTabWidget`）を持つメインウィンドウを中心に構築されます。

### メインウィンドウ (`MainWindow`)
- UI全体のメインコンテナ。
- `QTabWidget`をホストし、各機能タブのライフサイクルを管理します。

### UIタブ構成案（PMXエディタ準拠）

PMXエディタのタブ構成を参考に、Mayaのワークフローに最適化した形でUIのタブを再定義します。

*   **タブ1: ファイルI/O (File I/O)**
    *   **インポート (Import)**
        *   ファイル選択ボタン (`.pmd`, `.pmx`, `.vmd`)
        *   インポートオプション（スケール、法線、IK設定など）
        *   「インポート実行」ボタン
    *   **エクスポート (Export)**
        *   出力ファイル選択ボタン (`.pmx`)
        *   エクスポート対象の選択（シーン全体 / 選択オブジェクト）
        *   エクスポートオプション（テクスチャパス形式など）
        *   「エクスポート実行」ボタン

*   **タブ2: 情報 (Info)**
    *   モデル名（日本語/英語）の表示・編集
    *   モデルコメント（日本語/英語）の表示・編集

*   **タブ3: 材質 (Material)**
    *   シーン内のMMDマテリアル一覧（リスト表示）
    *   選択した材質の詳細情報（Diffuse, Specular, Ambient色など）
    *   テクスチャおよびスフィアマップのパス表示・編集
    *   描画フラグ（両面描画、地面影など）の編集

*   **タブ4: ボーン (Bone)**
    *   ボーン構造のツリービュー表示
    *   選択したボーンの詳細情報（親ボーン、変形階層、IK情報など）
    *   IKリンクリストの表示・編集
    *   ボーンフラグ（回転可能、移動可能、表示/非表示など）の編集

*   **タブ5: モーフ (Morph)**
    *   モーフの一覧表示（リスト表示）
    *   選択したモーフのタイプ（頂点、UV、ボーン、材質など）とオフセット情報
    *   Mayaのブレンドシェイプとの関連付け・解除
    *   スライダーによるモーフ適用率のプレビュー機能

*   **タブ6: 表示枠 (Display Pane)**
    *   表示枠の一覧表示
    *   選択した表示枠に含まれるボーンやモーフのリスト編集（追加/削除/順序変更）

*   **タブ7: 物理演算 (Physics)**
    *   **剛体 (Rigid Body)**
        *   剛体の一覧表示
        *   選択した剛体の詳細設定（関連ボーン、形状、物理パラメータなど）
    *   **ジョイント (Joint)**
        *   ジョイントの一覧表示
        *   選択したジョイントの詳細設定（接続剛体、可動範囲、バネ設定など）

*   **タブ8: 設定 (Settings)**
    *   プラグインの全般設定（UI言語、ログレベルなど）
    *   インポート/エクスポートのデフォルトオプション設定
    *   日本語<->英語変換辞書の管理

### ロギングコンポーネント (`LogViewer`)
- ログメッセージを表示するための専用ウィジェット。
- 既存の`mmd_tools.core.logger`と連携し、アプリケーション全体のログを一元的に表示します。

## ファイル構造

このモジュール設計をサポートするために、UIコードは新しい`mmd_tools/ui/`ディレクトリに再編成されます。

```
mmd_tools/
├── ui/
│   ├── __init__.py
│   ├── main_window.py      # MainWindowクラスを含む
│   ├── base_tab.py         # すべてのタブの抽象基底クラス
│   │
│   ├── components/
│   │   ├── __init__.py
│   │   └── log_viewer.py     # LogViewerウィジェット
│   │
│   ├── tabs/
│   │   ├── __init__.py
│   │   └── import_export_tab.py # インポート/エクスポートタブのビュー
│   │
│   └── presenters/
│       ├── __init__.py
│       └── import_export_presenter.py # インポート/エクスポートタブのプレゼンター
│
└── plugin_main.py        # UIを起動するためのエントリーポイント
```

## ロギングの統合

`LogViewer`コンポーネントは次のように実装されます：
1.  ログを表示するためのカスタム`QTextEdit`ウィジェット（`LogViewer`）を作成します。
2.  カスタム`logging.Handler`サブクラスを定義します。このハンドラの`emit`メソッドは、ログレコードをフォーマットし、フォーマットされた文字列とともにQtシグナルを発行します。
3.  このハンドラのインスタンスを、`mmd_tools.core.logger.get_logger()`を介して取得したルートロガーに追加します。
4.  `LogViewer`ウィジェットはハンドラのシグナルに接続し、メッセージを受信すると、そのテキストを表示領域に追加します。

これにより、アプリケーションのどこかで生成されたログメッセージ（`logger.info(...)`、`logger.error(...)`など）が、自動的にUIのログビューに表示されるようになります。

## 設定管理

UI関連の設定（例：ウィンドウのサイズ/位置、最後に使用したディレクトリ）は、`mmd_tools.settings`モジュールを通じて管理されます。
- タブまたはウィンドウが作成されると、その状態について設定モジュールに問い合わせます。
- UIで設定が変更された場合（例：チェックボックスが切り替えられた）、プレゼンターが`mmd_tools.settings`の適切な関数を呼び出して変更を永続化する責任を負います。

## 将来の拡張ワークフロー

新しい機能（例：「モーフツール」）を追加する場合は、次の手順に従います：
1.  `mmd_tools/ui/tabs/morph_tool_tab.py`に新しいビュークラスを作成します。
2.  `mmd_tools/ui/presenters/morph_tool_presenter.py`に対応するプレゼンタークラスを作成します。
3.  `main_window.py`で、新しいタブとそのプレゼンターをインスタンス化し、タブを`QTabWidget`に追加します。

このモジュラーアプローチは、新機能のコードを分離し、既存の機能への影響を最小限に抑えます。

## 実装タスクリスト（案）

以下に、このUI再設計を実現するための段階的なタスクリストを示します。各機能の実装と並行してテストを作成し、継続的な品質保証を目指します。

### フェーズ1: 基盤の構築

1.  **ファイル構造のセットアップ:**
    *   `mmd_tools/ui/` ディレクトリと、その配下の `components`, `tabs`, `presenters` ディレクトリを作成します。
    *   各ディレクトリに `__init__.py` を配置します。

2.  **メインウィンドウとエントリーポイントの実装:**
    *   `mmd_tools/ui/main_window.py`: `QMainWindow` を継承した `MainWindow` クラスを作成します。このクラスは `QTabWidget` を保持します。
    *   `mmd_tools/plugin_main.py`: `MainWindow` をインスタンス化して表示するためのエントリーポイント（起動用関数）を修正・実装します。Mayaのシェルフから呼び出せるようにします。
    *   **テスト:** `MainWindow` が正常に起動し、表示されることを確認するUIテストの雛形を作成します。

3.  **ロギングコンポーネントの実装:**
    *   `mmd_tools/ui/components/log_viewer.py`: ログを表示する `LogViewer` ウィジェットを作成します。
    *   `mmd_tools/core/log_handlers.py`: UIにログを転送するためのカスタム `logging.Handler` を作成します。
    *   `MainWindow` に `LogViewer` を統合します。
    *   **テスト:** カスタムハンドラがログを正しく `LogViewer` に転送することを検証する単体テストと、UI上での表示を確認する結合テストを作成します。

### フェーズ2: ファイルI/Oタブの実装

1.  **ビューの実装:**
    *   `mmd_tools/ui/base_tab.py`: 全てのタブが継承する抽象基底クラス `BaseTab` を作成し、共通のインターフェースを定義します。
    *   `mmd_tools/ui/tabs/import_export_tab.py`: `BaseTab` を継承し、ファイル選択ボタン、オプション、実行ボタンなどのUI要素を定義します。

2.  **プレゼンターの実装:**
    *   `mmd_tools/ui/presenters/import_export_presenter.py`: `ImportExportPresenter` クラスを作成します。
    *   ビューからのユーザーアクションを処理し、既存のインポート/エクスポート処理（`mmd_tools.io`）を呼び出すロジックを実装します。
    *   **テスト:** `ImportExportPresenter` のロジック（ファイルパスの検証、オプションの適用、ioモジュールの呼び出しなど）に対する単体テストを作成します。モックを使用して `io` モジュールへの依存を分離します。

3.  **統合とテスト:**
    *   `MainWindow` で `ImportExportTab` と `ImportExportPresenter` をインスタンス化し、タブウィジェットに追加します。
    *   **テスト:** インポート/エクスポート機能を実際に操作する結合テストを作成し、Mayaシーンにモデルが正しくロード/エクスポートされることを確認します。

### フェーズ3: 各機能タブの実装（テスト駆動開発）

以下のタブについて、フェーズ2と同様の「**テスト作成 → ビュー実装 → プレゼンター実装 → 統合**」のサイクルを繰り返します。優先順位の高いものから着手します。

1.  **情報 (Info) タブ**
2.  **材質 (Material) タブ**
3.  **ボーン (Bone) タブ**
4.  **モーフ (Morph) タブ**
5.  **表示枠 (Display Pane) タブ**
6.  **物理演算 (Physics) タブ**
7.  **設定 (Settings) タブ**

*   **開発プロセス:**
    *   **Step 1: テスト設計:** 各タブのプレゼンターが担うべきロジックを定義し、それに対する単体テストを先に作成します。
    *   **Step 2: 実装:** テストが通るように、ビューとプレゼンターのコードを実装します。
    *   **Step 3: 統合テスト:** タブをメインウィンドウに統合し、Maya上での手動テストおよび自動UIテストを通じて、機能が期待通りに動作することを確認します。
*   **注意点:**
    *   各タブは、対応するコア機能（例: `pmx_parser`, `morph_converter`）と連携する必要があります。
    *   Mayaシーンとの連携（オブジェクトの選択、情報の取得/設定）は、`mmd_tools.core.maya_utils` を通じて行います。プレゼンターから `maya_utils` の関数を呼び出す設計とします。

### フェーズ4: 最終化とリリース準備

1.  **UI/UXの改善:**
    *   全体のデザイン（スタイルシート、アイコンなど）を統一し、使いやすさを向上させます。
    *   ツールチップやヘルプテキストを追加します。
    *   ウィンドウサイズや分割バーの位置などを記憶・復元する機能を実装します。

2.  **総合テスト:**
    *   全機能を通したリグレッションテストを実施し、変更が既存機能に悪影響を与えていないことを確認します。
    *   様々なモデルデータや操作パターンでストレステストを行い、プラグイン全体の安定性を評価します。
    *   異なるMayaバージョンでの動作検証も行います。

3.  **ドキュメントの更新:**
    *   新しいUIの使用方法について、READMEや関連ドキュメントをスクリーンショット付きで詳細に更新します。
